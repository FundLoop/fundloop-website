# Internationalization

FundLoop now uses `next-intl` as the standard localization layer for the Next.js App Router.

## Locale model

- supported locales: `en`, `fr`, `es`
- default locale: `en`
- URL policy: always-prefixed
  - examples: `/en`, `/fr/participation`, `/es/support`
- unsupported locale prefixes such as `/de/...` are allowed to fall through to a normal `404`
- internal API handlers remain unprefixed
  - examples: `/api/internal/...`

## Routing and middleware

- locale routing is defined in [i18n/routing.ts](../../i18n/routing.ts)
- locale-aware navigation helpers live in [i18n/navigation.ts](../../i18n/navigation.ts)
- request-time message loading lives in [i18n/request.ts](../../i18n/request.ts)
- root redirect and locale-prefix enforcement live in [proxy.ts](../../proxy.ts)

FundLoop is on Next.js 16, where `proxy.ts` is the active root request-interception convention and `middleware.ts` is deprecated. Do not add a parallel `middleware.ts`; Next rejects projects that define both conventions.

Use the locale-aware `Link`, `useRouter`, and `usePathname` exports from `@/i18n/navigation` for internal navigation. Do not add new internal links with plain `next/link` unless the destination is intentionally external to locale routing.

## Dictionary layout and fallback

Messages live under [i18n/messages](../../i18n/messages).

Current domains:

- `shell`
- `home`
- `participation`
- `support`
- `metadata`

English is the baseline dictionary. Other locales are merged over the English base so missing keys fall back cleanly to English instead of breaking render.

## App Router pattern

- the localized app shell lives under `app/[locale]/`
- the `[locale]` layout is responsible for:
  - validating the locale
  - setting `<html lang>`
  - providing `NextIntlClientProvider`
  - localizing metadata

For localized public pages, prefer:

1. server page with `generateMetadata`
2. `getTranslations` for server-rendered copy
3. a small client child only when hooks, form state, or browser APIs are needed

## Expansion rule

When a task changes route structure, shell copy, or translation architecture:

1. update the relevant dictionaries
2. use locale-aware navigation helpers
3. update this doc and any related engineering docs before closing the task
