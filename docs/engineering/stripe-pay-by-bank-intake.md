# Stripe Pay by Bank intake (review-only)

FundLoop uses Stripe-hosted Checkout for a one-time, on-session Pay by Bank payment. Only EUR and GBP are modeled. The browser sends the project, payment, selected currency, expected minor-unit amount, and customer country; FundLoop never collects or stores bank credentials, client secrets, or raw provider payloads.

The command authenticates a project financial administrator and requires the current review Terms acknowledgement. Before command persistence or Checkout mutation, it authoritatively reads the exact test merchant account and dynamic payment-method configuration. The merchant country must be in Stripe's documented Pay by Bank business-location set, `pay_by_bank_payments` and the configuration must be active, and the recorded charge topology must be one of platform, direct, destination, or separate charges and transfers. UK and Finland customer paths are generally available. France, Germany, and Ireland remain denied unless exact private-preview enablement is configured for the same merchant account. Connected-account calls and events are bound to that connected merchant.

Checkout uses the dynamic configuration and never hard-codes `payment_method_types`. Returning from Checkout is never settlement. A verified Stripe signature triggers authoritative SDK reads of the unique Checkout Session, PaymentIntent, PaymentMethod, Charge, BalanceTransaction, or Refund. Command metadata, merchant account, Checkout Session, PaymentIntent, Charge, customer country, currency, amount, and payment method type are pinned; contradictory evidence fails closed.

Only `pay_by_bank` evidence with an available BalanceTransaction and conserved `gross = fee + net` creates a provisional custody reference and balanced neutral-ledger receipt. Processing, failure, cancellation, expiry, refund-pending, refunded, and refund-failed evidence is append-only and replay-safe. Failure, cancellation, expiry, and successful refund are durable terminal blocks against older settlement. Refund-pending invalidates any package source immediately. A successful refund reverses the original receipt exactly; a partial refund creates a separately conserved residual custody journal, but that residual remains quarantined from package eligibility. Refund failure can restore the unreversed settled source only for a newly validated package. Pay by Bank has no dispute workflow.

EUR and GBP custody routes and their USD functional conversions are provisional local/test fixtures, not accounting policy. Production is disabled at Edge, runtime-control, route, command, evidence, custody, package, and ledger layers. Provider capability or configuration absence is shown truthfully and performs no Checkout mutation.

## Validation boundary

Fresh local migration replay, executable SQL/RLS/RPC tests, strict Deno checks, typed provider fixtures, component tests, and exact 1440x900/390x844 browser captures are required. If the canonical Stripe sandbox lacks an eligible Pay by Bank capability/configuration, the provider smoke is expected-pending with zero mutation; deterministic signed-event/refetch fixtures remain mandatory. No production activation, private-preview enrollment, remote database mutation, payout, payable, or real value flow is included.
